# Pill — своя лёгкая «островная» панель для Windows

Аналог Dynamic Island для Windows (вдохновлён exuupery/island, но код, дизайн и персонажи свои, ничего не копируем).
Island тормозил: WebView2, ~950 МБ RAM и ~16% ядра в простое. Цель Pill: максимум лёгкости и функций, анимации не важны.

**Перед добавлением функций читать [ARCHITECTURE.md](ARCHITECTURE.md)**: бюджет лёгкости, потоки, правило `st()`, реестр WM_APP/таймеров, целевая структура модулей и план переезда.

## Документация после каждой фичи (обязательно)
Когда фича готова (собирается, тесты проходят), сразу запусти в фоне агента `docs-writer` (Sonnet, `.claude/agents/docs-writer.md`)
и передай ему: что сделано, что проверено руками, новые замеры, если есть. Сам продолжай следующую задачу, не жди.
Пока он работает, `.md` файлы в корне не трогай, чтобы не было конфликтов. Когда закончит, перескажи пользователю его отчёт, особенно найденные нарушения.

## Требования пользователя
- Rust, максимально легковесно: почти 0% CPU в простое и минимум RAM.
- Ставится на ПК и ноутбук одним portable `.exe`, без установщика.
- Функционал важнее анимаций. Главное, чтобы стабильно работало.
- Свёрнутая пилюля: время + батарея (на ПК без батареи только время).
- Раскрытие при наведении, сворачивание при уходе курсора (задержка 350 мс).
- Функции: музыка, буфер обмена, командная строка, переключатели (все четыре).

## Стек и устройство
- Чистый Win32 + GDI через крейт `windows` 0.58. Без браузерного движка и GUI-фреймворков.
- Тулчейн `stable-x86_64-pc-windows-gnu` (VS Build Tools не поставились: ошибка установщика 5008).
  Cargo лежит в `%USERPROFILE%\.cargo\bin`, в PATH может не быть.
- Окно: WS_POPUP + TOPMOST | TOOLWINDOW | NOACTIVATE | LAYERED, на WM_MOUSEACTIVATE возвращаем MA_NOACTIVATE (фокус не забираем).
- Слоёное окно (WS_EX_LAYERED): кадр рисуется в постоянный 32-битный буфер (`ui/surface.rs`) и выводится через UpdateLayeredWindowIndirect; форма и скругления сглажены своим растеризатором (`Canvas`), текст GDI. SetWindowRgn не используется.
- Перерисовка только по событиям: таймер часов раз в 1 с, наведение, клики.
- Single instance через мьютекс `Local\PillSingleInstance`.
- Per-monitor DPI v2, размеры в логических px и масштабируются через `scale()`.
- Сборка: `cargo build --release` → `target\release\pill.exe`. Перед пересборкой убить процесс `pill`, иначе exe заблокирован.

## Локальный API
Скрипты шлют события в пилюлю на `127.0.0.1:47821` (только с этого ПК; запросы из браузера отклоняются). Порт занят — API выключен (окно настроек, раздел «Агенты», пишет «API не поднялся: порт 47821 занят»). `/ping` отвечает «pill» и открыт; всё остальное требует ключ API: 32 hex в `%APPDATA%\Pill\settings.txt` (строка `api_key`, создаётся при первом запуске; в настройках → «Агенты» кнопка «Скопировать ключ»). Ключ шлют заголовком `X-Pill-Key: ключ`; `/notify`, `/task`, `/agent` принимают ещё `key=` в адресе или теле. `/hook` и `/open` только с заголовком. Без ключа 403. Ниже `KEY` — ваш ключ.

```powershell
$h = @{ "X-Pill-Key" = "KEY" }
# уведомление (secs 1..60, по умолчанию 4)
Invoke-WebRequest -UseBasicParsing -Headers $h "http://127.0.0.1:47821/notify?text=Рендер готов&secs=5"
# задача с прогрессом: в свёрнутой пилюле «Рендер 45%» (видно до 2 задач, хранится до 8)
Invoke-WebRequest -UseBasicParsing -Headers $h -Method Post -Body "id=render&title=Рендер&progress=45" http://127.0.0.1:47821/task
# готово: «✓ Рендер»
Invoke-WebRequest -UseBasicParsing -Headers $h "http://127.0.0.1:47821/task?id=render&state=done"
# ошибка: «✗ Рендер: ошибка»
Invoke-WebRequest -UseBasicParsing -Headers $h "http://127.0.0.1:47821/task?id=render&state=error"
```
```sh
curl -H "X-Pill-Key: KEY" "http://127.0.0.1:47821/notify?text=Hello&secs=5"
curl -H "X-Pill-Key: KEY" -d "id=render&title=Render&progress=45" http://127.0.0.1:47821/task
curl -H "X-Pill-Key: KEY" "http://127.0.0.1:47821/task?id=render&state=done"

```
Раскрыть панель на вкладке (`tab` = music | ctl | mon | feed | notifs | clip | cmd, другое значение сворачивает), для сверки вида по снимку экрана: `curl -H "X-Pill-Key: KEY" "http://127.0.0.1:47821/open?tab=feed"`.
Задача без обновлений 15 минут пропадает. Текст до 200 символов, название до 60. Кириллицу в `curl` лучше слать через `--data-urlencode`.

Агенты (`state` = work | ask | wait | done | gone; `ask` — нужно разрешение, `wait` — ждёт ответа):
```sh
curl -H "X-Pill-Key: KEY" "http://127.0.0.1:47821/agent?id=a1&name=pill&state=work&text=сборка"
curl -H "X-Pill-Key: KEY" "http://127.0.0.1:47821/agent?id=a1&state=done"
```
Открыть панель (для скриптов и снимков экрана, только с заголовком `X-Pill-Key`): `/open?tab=music|shelf|ctl|mon|feed|notifs`; поиск: `/open?tab=cmd|apps|clip|act` (режимы «Всё / Программы / Буфер / Действия»; параметр `q` убран, текст в строку поиска извне не подставляется); окно настроек: `/open?tab=settings&page=N` (раньше `q=N`); другое значение `tab` сворачивает панель.
Хук Claude Code (теперь ставится и убирается из окна настроек, раздел «Агенты»; ниже то, что оно пишет в `~/.claude/settings.json`; 9 записей: UserPromptSubmit, PreToolUse (с `matcher` «Agent»: только для описания задачи субагента, на каждый инструмент хук не гоняем), PostToolUse, PermissionRequest, Notification, Stop, SessionEnd, SubagentStart, SubagentStop; `async: true` у всех, кроме `PermissionRequest`: он синхронный, `timeout` 45, иначе ответ из пилюли не дойдёт до Claude Code):
```
curl.exe -s -m 2 --connect-timeout 1 -H X-Pill-Key:KEY --data-binary @- http://127.0.0.1:47821/hook
```
Вместо `KEY` установка вписывает ключ из `settings.txt` (у `PermissionRequest` `-m 40`). Хуки без ключа, со старым ключом или без новых событий субагентов (до этапа 23 их было 6): статус `hooks::HookState::Stale`, в настройках «нужно переустановить»; без переустановки `/hook` отвечает 403 и сессий Pill не видит.
`/hook` отвечает 200 с пустым телом: stdout хука попадает в контекст Claude. Единственное исключение: ответ на `PermissionRequest` по кнопке или Alt+Y/N (решение JSON; «всегда» только кликом), по Alt+T и таймауту тело пустое. Имя агента = папка проекта (cwd). Работающий без событий 30 мин и остальные 12 ч удаляются.

## Заметки
- Клики в окнах Pill через `PostMessage` (WM_LBUTTONDOWN в окно настроек и т. п.) проверять только из процесса, учитывающего DPI (`SetThreadDpiAwarenessContext` PER_MONITOR_AWARE_V2): иначе Windows пересчитывает координаты мыши в отправленных сообщениях и клик мажет (на 200% половина «кликов» не попадала).
- Баннеры (`feat/banners.rs`): `set`, `init` и реестр (`sys/banners.rs`) звать вне `st()`; `toasts_on()` в `ui/settings.rs::render` читается до `st()`. `ShowInActionCenter` не трогать: Pill читает центр уведомлений. Выключение возвращает баннер только из `banners.txt`; системные AUMID (`banners::skip`) не трогать, у их баннеров бывают кнопки.
- Структура `src/`: main, ids, app, shell, input, pill, `ui/`, `feat/`, `sys/`, `bg/`. `sys` и `bg` не знают `State`, `ui` не зовёт логику `feat`.
- Новый WM_APP, таймер, хоткей или пункт меню сначала в `ids.rs`, потом в ARCHITECTURE.md, раздел 5.
- Паника пишется в %APPDATA%\Pill\crash.log. Debug-сборка не линкуется (кириллица в пути), отлаживать релизом.
- WMI на ПК не подключать: его DLL дают ~3 МБ WS. `Displays::wmi()` ходит в WMI только если есть батарея.
- DDC/CI медленный (40–100 мс) и иногда отвечает старым значением: яркость только через воркер (`Job::SetBrightness`), после записи не перечитывать.
- Визуализатор: кадры `WM_APP_VIZ` рисуются мимо `render` в `State.viz_area`. Не слать новый кадр, пока не сброшен `PENDING`. `viz::refresh_want` сам берёт `st()`, внутри `st()` его не звать.
- `View.dim_from` — байтовый индекс (`text.len()`), по нему `split_at` в `collapsed::main_text`. Батарея идёт последней; если добавить часть текста после неё, индекс надо считать заново.
- Поиск (`Tab::Commands`) в `TABS` не входит: открывать через `input::activate(hwnd, mode)`, а не `on_tab`. `cmd::scan()` обходит меню Пуск в UI-потоке при каждом открытии, внутри `st()` его не звать (в обработчике `/open` пока зовётся: долг). `cmd::run_app` пишет `launches.txt`, `Entry.time` пишется в `clipboard.txt` третьим полем, старые строки без него читаются (`clip::parse_line`).
- Рисовать только через `Painter` (`fill`, `text`, `hit`, `viz` учитывают сдвиг `oy`). GDI обнуляет альфу под текстом, поэтому кадр обязан заканчиваться `Canvas::finish`, иначе текст прозрачный. `Surface::present(hwnd, dirty, pos)` (UpdateLayeredWindow) не звать внутри `st()`. Окно двигать и менять ему размер только через `shell::place` / `ui::render_sized` (размер и позиция в одном `present`), не `SetWindowPos` с размером: кадр будет дёргаться. `timeBeginPeriod(1)` только на время анимации (`Shell.hires`, парный `timeEndPeriod` в `on_anim_timer`). Буфер постоянный: визуализатор рисует в него поверх последнего кадра.
- Карточка: `peek::show` и `peek::hide` зовут `layout`, внутри `st()` их не вызывать. `bg::api::answer` пишет в сокет и берёт `HELD`: звать только вне `st()`, лок `HELD` и `st()` не вкладывать. `Hit::Peek` ловит и клик по самой карточке (`Dismiss`), он тоже отпускает хук без решения.
- Настройки: `Settings::save` пишет файл, звать вне `st()` (как в `shell::tray_menu`). Новый ключ добавляй в `parse` и `serialize`, неизвестные строки хранятся в `extra`.
- DrawTextW с пустой строкой падает: в ui::Painter::text есть проверка, не убирать.
- Win32 внутри `st()` нельзя: счётчики нагрузки читает `app::on_tick` до `st()`, VPN и рассылка темы идут через `winrt::Job`, а не из UI-потока. Потоков ровно 4 (UI, winrt, watch, api), пятый не заводить.
- Фоновый поток шлёт данные в UI через свой `static Mutex` + `PostMessageW`, не `SendMessage`. Для API это `feat::api::QUEUE` и `WM_APP_API`.
- Не использовать PDH (`Pdh*`, «GPU Engine», `PhysicalDisk`) для метрик: один счётчик добавляет 5–7 МБ, и после `PdhCloseQuery` память не возвращается. Брать `GetSystemTimes`, `NtQuerySystemInformation`, `IOCTL_DISK_PERFORMANCE`, `D3DKMTQueryStatistics`.
- Смещения `SYSTEM_PROCESS_INFORMATION` в `feat/sysmon.rs::parse_processes` захардкожены под x64. Буфер для `NtQuerySystemInformation` растёт при `STATUS_INFO_LENGTH_MISMATCH`.
- Чужие уведомления: событие `NotificationChanged` непакетному приложению недоступно (0x80070490), файл `wpndatabase.db*` событий не даёт, Bot API Telegram не видит личные сообщения, поэтому только опрос `GetNotificationsAsync` и только из воркера (`sys/toasts.rs`). Баннеры Windows прячет `feat/banners.rs` (`ShowBanner=0` в реестре), центр уведомлений не трогается.
- Карточка уведомления: высота зависит от наведения (`peek::set_hover` зовёт `layout`), поэтому внутри `st()` его не вызывать. `Peek` создавать через `Peek::new` (полей стало больше). Чат = программа + заголовок: `Hit::NotifGroup(id)` несёт id самого свежего, `forget_group` убирает все его уведомления. `Inbox::forget` остался только для тестов.
- `/hook` отвечает пустым телом, не менять: stdout хука попадает в контекст Claude Code. Решение пишется только в ждущее соединение `PermissionRequest` (`bg::api::answer`).
- Хоткеи ответа Alt+Y/N/T (3, 5, 6; номер 4 свободен, был Alt+A, не занимать) регистрируются только пока просьба на экране (`peek::show`/`hide`, вне `st()`), на это время они перехвачены у других программ. Новый путь убрать карточку (`s.peek = None`) должен идти через `peek::hide`, иначе хоткеи останутся занятыми. `peek::show`/`hide`/`resolve` зовут `layout`, а `bg::api::answer` берёт `HELD`: вне `st()`. Первые 500 мс после показа (`Peek.shown`, `ARM`) нажатия не принимаются, и пока `Peek::blocked()` (длинная команда не раскрыта) Alt+Y и «Разрешить» не действуют.
- Карточка просьбы: `Peek.agent` = id сессии (не имя папки), данные ищутся по `a.id == pk.agent`. Каждой просьбе свой `req` (`PeekKind::Ask { req }`), `answer(req, ..)` отвечает одному соединению, `release(id)` отпускает все запросы сессии. Строки `Peek.lines`: первый символ `!` (предупреждение), `=` (правило «всегда»), `…` (обрезано) — пометка, не код; `Peek::code()` их отделяет. Весь текст для человека (имя, цель, команда) пропускать через `agents::one_line` или `code_line`: они выкидывают bidi и невидимые символы.
- Ключ API: `Settings::ensure_key` создаёт `api_key` при первом запуске (`sys::random_hex`), установка хуков вписывает его в команду (`hooks::install(root, key)`); сменишь ключ в `settings.txt` — хуки надо переустановить. Ключ в буфер только через `sys::clipboard::set_secret` (с пометками «не сохранять»). Новый адрес API: решить, нужен ли ему ключ (по умолчанию да, как у всего кроме `/ping`).
- «Всегда» возвращает присланные Claude Code `permission_suggestions` как есть в `updatedPermissions`; без них кнопка = «Разрешить». Async-хук на решение влиять не может, поэтому `PermissionRequest` синхронный.
- `skip_focused` (по умолчанию включён) определяет «окно агента» по заголовку активного окна (имя проекта отдельным словом): редактор или браузер с папкой проекта в заголовке тоже подходит и прячет карточки «нужно разрешение» и «готов» (ждущий хук отпускается без решения, Claude Code спросит в терминале). Выключается `skip_focused=0` в `settings.txt`. `sys::wnd::focus_titled` и `foreground_title` зовутся из UI-потока вне `st()`; внутрь `st()` не переносить.
- Alt+1…4 (хоткеи 8..11) глобальные и занимаются только пока на экране вопрос агента с вариантами; новый путь убрать карточку вопроса идёт через `peek::hide`, как и для Alt+Y/A/N/T.
- Субагенты (этап 23): событие с `agent_id` приходит как `Update { sub: Some(..), sub_only: true }`; `sub_only` не трогает состояние, инструмент и запрос человека сессии и не заводит незнакомую сессию, новый путь разбора хука с `agent_id` должен ставить его, иначе субагент перепишет строку «что делает» у самой сессии. Описание задачи идёт в очередь `Agent.pending` из `PreToolUse(Agent)` и достаётся следующему стартовавшему; у фонового порядок `Named`/`Start` бывает любой, поэтому `Named` сначала вычёркивает свою задачу из очереди. `SubagentStop` без `SubagentStart` (внутренние агенты Claude Code) игнорируется. `UserPromptSubmit` с prompt «<task-notification>…» не запрос человека (иначе `Agent.note` и «работал N мин» сбиваются). `Agents::expire` возвращает true, когда пропал агент или закончивший субагент (`SUB_KEEP` 8 с): `app::on_tick` тогда зовёт `layout`, у чёлки другая ширина.
- `Agents::stack()` теперь в `feat/agents.rs` (раньше `ui/mascot::stack`): и `pill::view`, и `ui/collapsed.rs` берут стопку оттуда; в стопке и в `attention()` учитывается `Agent::busy()` (занят и тот, у кого работают субагенты), а не только `state`. `pill::Facts.kids` считается по первому в стопке; `Lead::width` растёт на `KID_DX` 12 за «детку» и 14 за «+N», новые части свёрнутого вида ставить с учётом этого.
- Island установлен в `%LOCALAPPDATA%\Island`. На время тестов его процесс закрыт, программа не удалена.
- Ctrl+Alt+H (`shell.hidden`): пока пилюля спрятана, окна нет, `layout` скрывает его по `visible()`. Всё, что показывает панель (`set_expanded(true)`, `peek::show` с просьбой), снимает `hidden`; новый путь показа добавлять туда же. `toggle_hidden` зовёт `input::close_panel` и `viz::refresh_want` вне `st()`.
- Перетаскивание ползунка: `SetCapture` и `ReleaseCapture` только вне `st()` (`on_click`, `on_mouse_up`); `WM_CAPTURECHANGED` в `st()` трогает только `State.drag`. Новый ползунок добавляется в `Hit` и в `matches!` в `on_click`, иначе тащить его не будет.
- Высота раскрытой панели: вкладка обязана звать `p.reach(y)` с нижним краем своего содержимого (поиск зовёт `reach` по списку результатов, в режиме «Буфер» `reach(EXPANDED_H)`). Без вызова `Painter.bottom` остаётся 0, высота не пересчитывается и держится от прошлой вкладки; слишком малый `reach` ужимает панель до 200.
- Окно настроек (`ui/settings.rs`): рисует в `surface::offscreen` на каждый `WM_PAINT`, зоны клика лежат в `SetWin.hits`, а не в `State.hits` (в `app::on_click` ветка `Hit::Set` пустая, клик ловит его `wndproc`). `open`, `hooks::status` и `hooks::apply` (файлы) звать вне `st()`; `WM_DESTROY` в `st()` только обнуляет `State.setwin`. Размер окна считается по DPI при открытии, `GetDpiForWindow` берётся на каждый кадр: при смене DPI они могут разойтись (не проверено).
- `hooks::apply` переписывает `~/.claude/settings.json` целиком с отступом 2: форматирование пользователя меняется (ключи и их порядок сохраняются). Битый файл не трогается. Хук с адресом `127.0.0.1:47821/hook` считается нашим и заменяется при переустановке. Копия в `settings.json.pill-backup` одна.
- Обновление (`feat/update.rs`): `update::tick()` зовётся из `app::on_tick` вне `st()`, `swap()` и `check`/`download` тоже вне `st()` (`check`/`download` только в воркере, сеть в UI-потоке нельзя). Путь exe не менять: хуки Claude Code и автозапуск указывают на него. Формат релиза (этап 20 обязан его делать): тег `vX.Y.Z`, файлы `pill.exe` и `pill.exe.sha256` (hex или строка `sha256sum`). `STATUS` лочить коротко и не вкладывать в `st()`. После обновления новый процесс ждёт мьютекс до 10 с и порт API до 30 с, старый держит их, пока не дождётся его первого тика; нельзя возвращаться из `main` до `hand_over()`, иначе откат не сработает. Обычный запуск стирает `pill.exe.new` и `.old` рядом с exe.
- Пользователь общается по-русски, коротко и неформально. Отвечать тоже по-русски.
- Просьба агента: `feat/agents.rs::ask_phrase` ждёт `tool` в виде «Инструмент: цель» (`Edit: путь`); пустой `tool` даёт «просит разрешение». `PeekHit::More` («подробнее») обрабатывается в начале `peek::on_hit` и не трогает `HELD`: решения не даёт и хук не отпускает.
- «Готов» (`PeekKind::Done`) текст ответа не показывает: `Notice::Done.text` в `feat/api.rs` не используется (`let _ = text`). Время работы берётся из `Agent.started`, он ставится только при новом запросе человека.
- Полка: `sys::dragdrop::drag_out` (`SHDoDragDrop`) и `DragDetect` в `shelf::on_press` — модальные циклы, пока тащат, UI-поток крутит сообщения (приходят и `WM_APP_*`). Звать только вне `st()`, как и `Item::probe` (`fs::metadata`) и запись `shelf.txt`.
- Колбэки `IDropTarget` (`sys/dragdrop.rs`) `State` не трогают и `st()` не зовут: только `DROPPED` (static Mutex) + `PostMessageW(WM_APP_DROP)`, остальное в `feat::shelf::on_drop`. Свой же файл, который тащат с полки, окно не принимает (`OUTGOING`).
- Новая вкладка в шапке: `TABS` в `app.rs` (сейчас 4: Музыка, Полка, Система, События), диспатч по `Tab` в `ui/mod.rs`, ветка в `app::on_tab`; `Tab::Shelf` ставит и `on_drop` (если не идёт поиск). Вкладка обязана звать `p.reach(y)`.
- Полка хранит пути, не файлы: пропавший файл убирается при щелчке. Новые миниатюры только через `Job::Thumb` (воркер, файл до 40 МБ в память), `Item.asked` не даёт слать повторно.
- Раскрытие после клика: `shell::hold_hover()` (`Shell.no_hover`, 10 с) ставят `ctl.rs` (Ctl::Shot) перед `close_panel` и `peek::on_hit` при щелчке по карточке (только если `shell::cursor_inside`, иначе `on_mouse_leave` не придёт и запрет повиснет). Пока он действует и карточки нет, `on_mouse_move` не раскрывает панель; `on_mouse_leave` его снимает. Новое действие, после которого окно уменьшается под неподвижным курсором, должно звать `hold_hover` (его WM_MOUSEMOVE раскроет панель снова).
- Снимок: `sys::clipboard::read_image` и `snap::save_as` (`IFileSaveDialog`, модальный COM-диалог) звать только вне `st()`. Одна картинка приходит двумя `WM_CLIPBOARDUPDATE` с разными номерами, поэтому повтор отсекается и по `GetClipboardSequenceNumber`, и по отпечатку (длина + каждый 4096-й байт + хвост); без отпечатка писалось два файла. Кодирование DIB в PNG и запись только в воркере: `Job::Snap { image, keep }`, результат `static SNAP` + `WM_APP_SNAP`; `prune_snaps` не трогает файлы с полки (`keep`). Уведомление не перебивает карточку снимка (`peek::show`), иначе пропадёт тост «Ножниц».
- Поверх всех окон: `shell::raise` зовётся из колбэка `SetWinEventHook` и из `TIMER_RAISE`, внутри `st()` его не вызывать и `State` в колбэке не трогать (колбэк может прийти посреди модального цикла, hwnd берётся из `static shell::MAIN`). Для невидимого окна `raise` ничего не делает. Другое окно, которое постоянно ставит себе TOPMOST, может «перетягиваться» с чёлкой на каждую смену активного окна (не проверено).
- Уведомления Telegram Desktop не попадали в чёлку из-за выключенного главного переключателя уведомлений Windows (`PushNotifications\ToastEnabled=0`, нашли 19.11; после включения Telegram прислал первое системное уведомление). Вообще же они не попадают в чёлку, если Telegram рисует свои всплывающие окна, а не системные тосты: `UserNotificationListener` видит только системные. Проверка: в `HKCU\Software\Microsoft\Windows\CurrentVersion\Notifications\Settings` нет записи Telegram, значит он ни разу не слал уведомление Windows (у пользователя так и было). Код не меняется. Решение на стороне пользователя: в Telegram включить системные уведомления Windows (Настройки → Уведомления и звуки, пункт про системные уведомления); баннеры можно спрятать настройкой «Прятать баннеры Windows» или в Параметрах Windows, но «Показывать в центре уведомлений» (`ShowInActionCenter`) оставить включённым, иначе Pill их тоже не увидит. Пока окно Telegram активно, он уведомлений не шлёт вовсе. Карточку Telegram в чёлке пользователь ещё не подтвердил.
