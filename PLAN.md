# План: новый дизайн Pill по кускам

Составлен 2026-11-14. Макеты и обоснования: https://claude.ai/artifact/9pAtQ8kyWNqDz1BumW9gKk (страница приватная, открывается из аккаунта владельца).
Перед работой читать [ARCHITECTURE.md](ARCHITECTURE.md): бюджет лёгкости, 4 потока, правило `st()`.

## Как работать по плану

- Один кусок = одна сессия = один коммит. Куски внутри этапа идут по порядку, этапы 3–5 можно менять местами.
- После каждого куска: `cargo build --release`, `cargo test --release`, замер (CPU в простое за 60 с, WS, приватная память, размер exe), потом агент `docs-writer`.
- Размер куска: **мелкий** (до ~150 строк), **средний** (150–400), **крупный** (больше 400 или есть неясность, сначала проба).
- Потолки из ARCHITECTURE: WS ≤ 30 МБ (сейчас 26,5), приватная ≤ 10 МБ (4,8), exe ≤ 1,5 МБ (771 КБ), потоков ровно 4.

## Решения, принятые 2026-11-14

- «Буфер» и «Команды» больше не вкладки, а режимы одной строки поиска (Alt+Space, Ctrl+Alt+V, лупа в шапке).
- Вкладки: Музыка, Полка, Система, События. Пока полки нет (до этапа 8), вкладок три.
- Режимы ПК: тишина от Pill и закрытие программ по списку. Включение вручную, плюс подсказка в пилюле. План питания и запуск программ не трогаем.
- Передача файлов: сначала с ПК на телефон по коду на экране. Приём с телефона, портал на ноутбук и общий буфер отложены.
- Маскоты рисуются кодом, без картинок и без своего таймера (кадр глаз с секундного тика).

## Этап 6. Разрешения и вопросы из пилюли

Самый рискованный этап. Зависит от 0.3 и 4.2.

### 6.0 Живая проверка того, что уже есть (обязательно первой)
- Механизм написан (`bg/api.rs::HELD`, ответ `hookSpecificOutput.decision.behavior = allow | deny`), но с настоящим Claude Code не проверен. Проверить: хук запроса разрешения должен быть не `async` и с тайм-аутом больше 30 с; «Разрешить» и «Отклонить» действительно срабатывают; пустой ответ и тайм-аут возвращают запрос в терминал.
- По документации хуков выяснить, можно ли ответом передать «всегда» и можно ли отвечать на вопросы агента. Если нет, 6.2 и 6.3 урезаются.

### 6.1 Очередь запросов (средний)
- Ждущий адрес уже есть и поток API не блокирует. Осталось: несколько запросов сразу (сейчас карточка одна, новый запрос заменяет старый на экране), счётчик «1 из 2», показ следующего после ответа.

### 6.2 Карточка запроса (средний)
- Есть: имя агента, текст запроса, кнопки «Отклонить» и «Разрешить», клик по карточке отпускает запрос в терминал, карточка ждёт ответа.
- Осталось: по какому запросу пользователя, инструмент отдельной строкой, команда целиком или изменения с +/−, кнопки «Всегда» и «В терминал», ключ автораскрытия в настройках.
- Глобальные хоткеи регистрируются при появлении запроса и снимаются при ответе. Предложение: Alt+Y, Alt+A, Alt+N, Alt+T.

### 6.3 Вопросы агента (средний)
- Варианты кнопками, выбор Alt+1…4, последний пункт уводит в терминал.

### 6.4 Установка хуков из трея (средний)
- Пункт трея добавляет и убирает записи в `~/.claude/settings.json`. Свои записи помечать, удалять только их, перед правкой делать копию файла.

### 6.5 Звуки и «не мешать» (средний)
- Системные звуки (`PlaySound` с псевдонимами), свои не встраивать. Ключи: вкл/выкл, тихие часы. Ошибка инструмента не звонит, звонит упавший ход.
- Не уведомлять, если окно терминала этого агента в фокусе, и переход к терминалу по клику: сначала проба, как сопоставить сессию с окном (VS Code и Windows Terminal по-разному). Может оказаться недостижимым.
